# Как не потерять данные и залить свои изменения

Ситуация: данные уже есть на сайте и в GitHub, локально на этом ПК их нет (или вы не уверены). Нужно подтянуть данные с GitHub, не затереть их при пуше и залить свои изменения в коде.

---

## Кратко

1. **Сначала** подтянуть с GitHub всё актуальное (включая папку `data/`) — **pull**.
2. **Потом** закоммитить и отправить свои изменения кода — **push**.
3. Данные в репозитории при этом **не трогаются** (вы не удаляете и не перезаписываете `data/`), они остаются на GitHub.

---

## Пошагово

### Шаг 1. Сохраните свои локальные правки (если ещё не закоммичены)

Если вы правили файлы и не хотите их потерять:

```powershell
cd c:\r\dnd-site
git status
```

- Если видите изменённые файлы (например `server/db.js`, `DEPLOY.md`) и хотите их сохранить:
  - либо сразу закоммитить в отдельную ветку (шаг 4);
  - либо временно спрятать: `git stash push -m "my code changes"` — тогда после pull можно будет вернуть: `git stash pop`.

Если всё уже закоммичено в `main` — переходите к шагу 2.

---

### Шаг 2. Подтяните с GitHub всё актуальное (включая данные)

Так вы получите с сервера последнее состояние репозитория, в том числе папку `data/` (партии, персонажи, портреты), если она там есть.

```powershell
cd c:\r\dnd-site
git fetch origin
git pull origin main
```

(Если ваша основная ветка называется иначе, подставьте её имя вместо `main`.)

- Если **pull прошёл без конфликтов** — у вас теперь локально и актуальный код, и данные из GitHub. Переходите к шагу 3.
- Если **git пишет про конфликты** — не делайте `git push`. Переходите к разделу «Если возникли конфликты» в конце файла.

---

### Шаг 3. Убедитесь, что данные подтянулись

Проверьте, что появилась папка с данными:

```powershell
dir data
dir data\portraits
```

Должны быть (в зависимости от того, что уже есть на GitHub):

- `data/db.json` — пользователи и, в старом формате, персонажи/сессии/карта;
- и/или `data/characters.json`, `data/sessions.json`, `data/map.json` — если сайт уже сохранял в новом формате;
- `data/portraits/` — файлы портретов (фото персонажей).

Если чего-то из этого нет — значит, на GitHub этого ещё не было (например, новый формат появится после первого сохранения на обновлённом сайте). Это нормально.

---

### Шаг 3.1. (По желанию) Перевести данные в новый формат

Если у вас один файл `data/db.json` со всем внутри (пользователи, персонажи, сессии, карта) и вы хотите сразу перейти на новый формат (четыре файла) **без изменения данных**, выполните один раз:

```powershell
cd c:\r\dnd-site
node server/scripts/migrate-db-to-split-format.js
```

Скрипт прочитает `data/db.json`, разложит данные по файлам `data/db.json` (только пользователи), `data/characters.json`, `data/sessions.json`, `data/map.json`. Портреты в `data/portraits/` не трогаются. После этого можно закоммитить и запушить эти изменения вместе с кодом (шаг 4).

---

### Шаг 4. Закоммитьте и запушьте свои изменения кода

Теперь можно безопасно отправить свои правки. Вы **не** удаляете и **не** перезаписываете `data/` своими коммитами — вы только добавляете изменения в коде.

```powershell
git status
git add server/db.js DEPLOY.md
# если делали шаг 3.1 — добавьте новые файлы данных: git add data/
# или добавьте все изменения: git add .
git commit -m "Разделение db на несколько файлов, обновление DEPLOY"
git push origin main
```

После пуша:

- Ваш код будет на GitHub.
- Данные в `data/` на GitHub останутся как были (или дополнятся при следующих сохранениях на сайте).

---

### Шаг 5. (По желанию) Сделайте локальную копию данных

Чтобы точно не потерять данные, можно один раз скопировать папку `data/` в безопасное место (вне репозитория):

```powershell
Copy-Item -Path "c:\r\dnd-site\data" -Destination "c:\r\dnd-site-data-backup" -Recurse
```

Или заархивировать и положить архив куда-то отдельно. Это не обязательно для «залить изменения», но полезно как бэкап.

---

## Важно

- **Не удаляйте** папку `data/` в репозитории и **не добавляйте** корневую `data/` в `.gitignore`. Иначе при следующем push данные на GitHub можно потерять или перестать синхронизировать.
- В `.gitignore` игнорируется только `server/data/` — это локальное хранилище при работе без GitHub. Корневая папка `data/` в репозитории должна оставаться под версией.

---

## Если возникли конфликты при pull

1. Не паникуйте и не делайте `git push --force`.
2. Посмотрите, какие файлы конфликтуют: `git status` (будут помечены как `both modified` или подобное).
3. Если конфликт только в **коде** (например, в `server/db.js`):
   - откройте файл, найдите блоки `<<<<<<<`, `=======`, `>>>>>>>`;
   - оставьте нужный вариант (или объедините правки вручную), удалите маркеры;
   - сохраните файл, затем:  
     `git add путь/к/файлу`  
     `git commit -m "Разрешение конфликта"`  
     `git push origin main`
4. Если конфликт в **data/db.json** (или других файлах в `data/`):
   - данные с GitHub обычно важнее (то, что на сайте). Можно принять версию с сервера:  
     `git checkout --theirs data/db.json`  
     `git add data/db.json`  
   - затем закоммитить разрешение конфликта и сделать push, как выше.

После разрешения конфликтов данные с GitHub у вас будут локально, а ваш код уйдёт на GitHub через push.

---

## После обновления кода на GitHub

Когда вы задеплоите новый код (например, на Render):

- Сайт при **первом сохранении** создаст в репозитории новые файлы: `data/characters.json`, `data/sessions.json`, `data/map.json` (если их ещё нет). Старый `data/db.json` будет прочитан, данные не пропадут.
- При следующем `git pull` вы подтянете и эти новые файлы.

Кратко: сначала **pull** (получить данные и код с GitHub), потом **push** (отправить свои правки) — так вы и данные не потеряете, и изменения зальёте.
